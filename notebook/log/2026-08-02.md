# 2026-08-02 — messaging and philosophy pass before v0.1 publish

Docs-only session. No code touched (deliberate: publish is tomorrow night).
Trigger: Toby's read of the README landed on the headline claim being subtly
wrong — *"storage is not memory"* asserts a category difference he doesn't
believe. Storage is a kind of memory; the thing being tested is that episodic
consolidation and integration are necessary for understanding.

## What changed

**The claim.** Retired "storage is not memory". New headline:

> Continual learning agents need expanding memory: episodic memory growing across
> sessions; semantic memory growing across episodes.

Workshopped through ~6 variants. What survived and why:

- *"Expanding memory"* as the header noun — makes the two clauses two levels of
  the same operation (sessions accumulate episodes; episodes accumulate into
  concepts) rather than a list of two requirements. Positive commitment
  (additive, monotone) rather than a negation.
- **"semantic" over "concept"/"conceptual"** — episodic/semantic is the standard
  Tulving pair. Coining a term for a thing that already has a name is a crackpot
  tell; using the standard pair buys the psychology literature for free. Accepted
  cost: collision with NLP's semantic-search sense.
- **"across sessions" not "with sessions"** — "growing with sessions" describes
  something CL-Bench already measures (a quantity that gets bigger over an
  unbroken run) and loses the discontinuity, which is the entire contribution.
- Known ambiguity, accepted: **"across" means different things in the two
  clauses** (crossing a boundary vs ranging over a set). Mitigation is the
  adjacent gloss, which puts "abstracted" in the first sentence underneath.
  Reserve fix if the slogan ever travels alone: *"out of episodes"*. Rejected
  *"over episodes"* — "over" only reads as ranging-over inside the idiom
  *abstraction over X*, and bare "growing over" pulls toward the duration sense,
  so it's a wash on ambiguity and costs the parallelism.
- Also retired: *"the first is cheap — write to disk"* was kept, on the judgement
  that conceding everything concedable is rhetorically stronger than defending a
  half-point about index maintenance.

**The ICL correction** — the substantive fix of the session, and Toby caught it.
Both docs said *"in-context learning produces access without integration."* False:
transformers integrate richly within a window. Reframed to *where the abstraction
goes* (query time, discarded with the process). Full reasoning and the resulting
three-position table in [recording vs memory](../notes/recording-vs-memory.md).
The replacement claim is strictly better — honest about the transformer, and it
yields a structural argument for why retrieval should fail at aggregation
specifically (retrieval selects by query; you cannot abstract over what you did
not retrieve).

**Recording vs memory** added as a third term in the taxonomy, from Toby's
introspection about recalling gist without events. See the note; the
reconstruction literature (Bartlett, Loftus, Schacter & Addis, Hassabis 2007,
fuzzy-trace, CLS) is listed there as pointers — **not read properly yet, no
reference notes exist**.

**Profile-across-rungs** fell out of it: a perfect Recall score is what a
*recording* looks like, so the informative quantity is the shape across rungs,
not the height at any one. New ROADMAP subsection. Costs no code.

**Storage budget promoted** *Exploring* → *Likely*, on a better argument than the
one it had. Was justified by deployment setting (edge vs server), which made it
look niche. Real reason: **if storage is free, a recording is never punished**, and
we currently have exactly one way to separate recording from memory (probes a
recording can't answer). A capacity constraint is the second, independent one.
Toby also wants to test at pre-training scale (many GB), where keeping the
recording stops being free even on a server.

**ADUS section added to ROADMAP.** Channel taxonomy (C-N/C-X/C-T/C-S) → SUT
classes, claims 4 and 9 as what the instrument is for, explicit that it's the
author's own framework. Kept out of the README on credibility-coupling grounds —
reasoning in [ADUS mapping](../notes/adus-mapping.md).

## Verified, not assumed

CL-Bench really has no survivable discontinuity: `reset()` is documented "for
resetting between different task instances, not for resetting learned knowledge
within a task", and `reset_between_instances=True` is used only to compute the
stateless baseline (`runner.py:194`). But the fair statement isn't "CL-Bench does
long contexts" — it's that **CL-Bench is agnostic about where state lives and
therefore cannot tell in-memory from on-disk apart**, because the process is never
killed. Same claim, no territorial edge. Matches what `CL-BENCH-TUTORIAL.md`
already concluded.

## Second pass (same day) — three decisions closed

**Mathematics: real, with a control arm.** ROADMAP §"Two invariants" now states the
condition rather than the blanket invented-only rule. Real mathematics past a
measured knowledge frontier is admissible *provided the elicitation ceiling is
measured as a control arm* — base model with maximal in-context help, consolidation
counted only where it beats what elicitation recovers. Rationale (behavioural
absence ≠ representational absence; CR-21 as the measured instance) is in the doc.

**Metrics: routed, not reordered.** See [ADUS mapping](../notes/adus-mapping.md) for
the full reasoning. Short version: the uniform sweep was the headline metric that
cannot answer the headline claim, but swapping in phased store removal would mean
leading with a driver that has no calibration ladder. So both are first-class and
each doc says which question it answers. README, phased-store-removal.md updated;
the phrase "retention-bench's headline measurement" is gone from both.

**Ambition stated, as a measurement aim.** New ROADMAP §"What would count as
success" near the top, plus one sentence in README §"Scope and limits".

Structural point worth keeping: Toby's ambition is *"solve continual learning"* —
concretely, a learning algorithm that gets LLMs to persistently acquire new and
corrected understanding in mathematics, coding and other domains. That is the
**system's** ambition and it lives in constructive-retention / adus-harness. What
went into this repo is the **instrument's** version: to be able to *detect* such a
system. Keeping those separate matters — stating the system ambition in the
benchmark's own agenda doc would say, in the benchmark's voice, that its author
wants a particular class of system to win. That worsens the co-design hazard the
document exists to disclose.

Side effect: the new section fixes both tier mismatches (revision is only *Likely*,
application only *Exploring*) without inflating any tier, by separating **target**
from **schedule** and saying they differ on purpose.

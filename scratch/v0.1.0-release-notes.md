# retention-bench v0.1.0

First public release. **This is a research instrument, not a benchmark** — there is no
leaderboard and no submission process. It is the workbench a research programme uses, published
so its design can be inspected and pointed at other systems.

## What it does

retention-bench adopts [Continual Learning Bench](https://github.com/pgasawa/continual-learning-bench)'s
runner, task interface and evaluation contract, and points them at a different question: does
what a system learned during a run survive a discontinuity that erases working state, and is
what survives *integrated* or merely *stored*?

Two pieces make that measurable:

- **A hard RESET** — a `SIGKILL`-and-respawn discontinuity across which only an on-disk
  survive-directory persists. Nothing in memory carries over, so any score that survives was
  carried through the survive-dir.
- **A mechanism-agnostic SUT contract** — read a stage, optionally mutate the survive-dir,
  write a response. Fine-tuning, structural growth, notes and retrieval are all modes above one
  process-level interface, and the harness cannot tell them apart.

The headline output is a reset-axis retention curve. Normalised retention is
`(R − P) / (C − P)` — how much of the *learnable band* between the stateless prior `P` and the
unbroken ceiling `C` survived `k` hard resets. Bands where `C ≈ P` are excluded rather than
scored.

## What is in this release

- The `SubprocessSystem` adapter, hard-reset semantics, and three reset schedules.
- Two drivers, routed by the claim being made: the uniform `--reset-every k` sweep (graceful
  degradation under repeated erasure) and phased store removal `--reset-at` (did capability
  migrate into what persisted). They answer different questions and the *same SUT* can score
  1.000 on one and 0.000 on the other — see `docs/phased-store-removal.md`.
- One Retention-Bench-native task, `symbolic_associative_retention`: deterministic nonce-symbol
  associations with recall and two-hop composition probes, including a never-bridged held-out
  split.
- Five keyless reference SUTs forming a calibrated ladder, plus bring-your-own-task support via
  `--task-spec`.
- Bootstrap confidence intervals, post-reset windows `W(m)`, and `ε` relative to `r_max`.

## Reference ladder — the reproducible numbers

Deterministic, offline, no API key. `./run.sh ladder` reproduces these exactly from a clean
checkout:

| SUT | Mechanism | `P` | `C` | `R(k=55)` | `R(k=111)` | Normalised retention |
|---|---|---:|---:|---:|---:|---:|
| `random_guess` | uniform guess from the task vocabulary | 0.027 | 0.027 | 0.027 | 0.027 | **EXCLUDED** (band = 0) |
| `no_state` | in-RAM only; never touches the survive-dir | 0.000 | 0.571 | 0.000 | 0.000 | **0.000** |
| `reset_lossy` | geometric forgetting, 1% per reset | 0.000 | 0.571 | 0.313 | 0.196 | **0.547 → 0.344** |
| `bounded_memory` | FIFO-capped survive-dir window (cap 40) | 0.000 | 0.429 | 0.429 | 0.429 | **1.000** |
| `associative_memory` | full survive-dir persistence | 0.000 | 0.571 | 0.571 | 0.571 | **1.000** |

The metric separates the stateless floor from full retainers, places a geometrically-forgetting
rung strictly between them, and sits every rung against a measured chance line. Interpretation
is in `docs/reference-ladder.md`.

## What this release does not do

Stated plainly, because an instrument's limits are part of its specification:

- **No language model has been measured.** The ladder covers keyless synthetic reference systems
  only. The central claim is unfalsified in either direction; the first real LLM measurement is
  the immediate next step.
- **One owned task.** CL-Bench's own tasks run through the same seam, but the probe families on
  the roadmap — aggregation, revision, application — do not exist yet.
- **No constructive learner ships here.** The instrument is co-designed with
  `constructive-retention`, a sibling project by the same author that is not yet public. That is
  a genuine validity hazard; we name it, and we publish the probe design and thesis in
  `docs/ROADMAP.md` *before* those systems are measured, so the design is timestamped ahead of
  any favourable result.
- **Cost is not settled.** Token counts are not architecture-neutral, so no cost metric is
  published as authoritative.
- **The phased ladder does not exist.** The keyless reference ladder is calibrated on the
  uniform sweep only.

## Reproducing

Requires **Python 3.13+**.

```bash
git clone https://github.com/symbolfarm/retention-bench && cd retention-bench
python3.13 -m venv .venv && . .venv/bin/activate
pip install -e .
pip install -e "git+https://github.com/pgasawa/continual-learning-bench.git@9cc63c0f429048b843e8d43ac4f2b0ea4df13724#egg=cl-benchmark"
./run.sh smoke
./run.sh ladder
```

**The `cl-benchmark` pin must be installed editable.** As a wheel it silently drops the task
data files its tasks load at runtime, and every task construction fails. Use `pip` for that step
even if you otherwise use `uv` — `uv pip install -e` rejects git URLs.

The pin is a commit SHA rather than a version, and it is the one input this tag cannot freeze:
`9cc63c0f429048b843e8d43ac4f2b0ea4df13724`.

## Versioning

Versions here track the **measurement contract**, not the code. Patch releases keep published
numbers valid; anything that changes what an existing number *means* — the retention formula,
reset semantics, task content or scoring — is at minimum a minor bump and will say so in these
notes. See `RELEASING.md`.

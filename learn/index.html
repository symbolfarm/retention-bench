What survives when the agent does not?

Retention Bench is a research instrument for asking what a system learned during a run—and whether that learning survives a real discontinuity. Start with the question, then follow each design choice down to the code.

The story

Nine branches, from purpose to limitations

This is an explanatory order, not the repository’s directory order. Technical facts arrive only after the question that makes them necessary.

01

The suspicion

Agents can write notes or replay logs across sessions. But a recording is not automatically an integrated memory: the system may re-derive the useful abstraction from scratch every time.

02

The measurement problem

A raw post-training score is ambiguous. Was the system already capable? Could it learn at all? Did disruption erase anything? The instrument needs a measured prior, ceiling, and retained performance.

03

The discontinuity

A logical reset() asks the SUT to forget. Retention Bench instead kills the process group. Only files already flushed to the survive-directory can cross the boundary.

04

The arms

P repeatedly wipes durable state, C runs without resets, and R(k) keeps disk state across k measured hard resets. Together they define the learnable band.

05

Two reset questions

Uniform resets ask about graceful degradation during repeated disruption. One reset after learning, with the episodic store removed, asks whether capability migrated into a durable artifact.

06

The task

The current native task teaches nonce object→attribute facts and attribute→bin rules. Recall tests one hop; transfer joins two. Held-out objects stop every transfer answer becoming a pre-written shortcut.

07

The journey

CL-Bench emits a query. SubprocessSystem sends one JSON line to the SUT, validates one reply, records resources, observes completion, and may kill the process before the next query.

08

The sharp edges

Reset ordinals are counted after completed instances. The final boundary never resets. Storage is measured before the kill. A collapsed learnable band is excluded, not promoted into a precise-looking score.

09

The honest limits

The instrument has one owned synthetic task, no completed real-LLM measurement, and a co-design validity hazard. Today it demonstrates a measurement approach—not the central thesis.

The key formula, in plain language

(R − P) / (C − P) asks: of the improvement this particular system could acquire during this task, how much was still visible after resets? When C − P is too small, there was no credible learnable signal, so the curve is marked excluded.
